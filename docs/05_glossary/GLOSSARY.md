# GLOSSARY

## Scopo

Questo documento definisce il significato dei principali termini utilizzati in IMAGO.

Non rappresenta un glossario tecnico.

Rappresenta il linguaggio comune del progetto.

Ogni termine deve mantenere lo stesso significato in:

- documentazione;
- codice;
- prompt;
- report;
- sviluppo futuro.

Se un termine cambia significato, il Glossary deve essere aggiornato.

---

# Action Strategy

Insieme delle azioni suggerite dal Core a partire dalla Visibility Analysis.

L'Action Strategy non contiene nuova interpretazione.

Trasforma la comprensione in azioni operative.

Esempi:

- piano di miglioramento;
- CV;
- checklist;
- coaching;
- simulazione;
- prossimi passi.

---

# Collection Goal

Obiettivo di raccolta delle evidenze.

Non rappresenta una domanda.

Non rappresenta un quiz.

Non rappresenta un esercizio.

Descrive ciò che il sistema vuole riuscire ad osservare.

L'applicazione decide come raggiungerlo.

---

# Collection Strategy

Strategia utilizzata per raccogliere le evidenze.

Interview è una Collection Strategy.

Learning utilizza una Collection Strategy differente.

Il Core non conosce le modalità di raccolta.

---

# Core

Motore generale di IMAGO.

Ha il compito di:

- comprendere;
- costruire un modello;
- raccogliere evidenze;
- confrontarle;
- proporre azioni.

Il Core non appartiene ad alcun dominio specifico.

---

# Decision Context

Contesto decisionale nel quale verrà utilizzata una rappresentazione.

Esempi:

- selezione;
- candidatura;
- colloquio;
- orientamento;
- assessment.

Lo stesso contenuto può essere rappresentato in modo differente in contesti differenti.

---

# Dimension

Grande area osservabile del Reference Model.

Una Dimension contiene uno o più Signals.

---

# Evidence

Informazione osservabile utilizzabile dal sistema.

Può provenire da:

- CV;
- colloquio;
- documenti;
- trascrizioni;
- manuali;
- questionari;
- dati runtime.

L'Evidence rappresenta l'unità fondamentale del Core.

---

# Evidence Collection

Processo mediante il quale il sistema raccoglie nuove evidenze.

---

# Explainable Intelligence

Principio secondo cui ogni suggerimento prodotto deve essere spiegabile.

Il sistema non deve limitarsi a produrre output.

Deve spiegare il motivo delle proprie conclusioni.

---

# Input Bundle

Insieme delle sorgenti disponibili.

L'Input Bundle non contiene interpretazioni.

Contiene solamente fonti informative.

---

# Observed Evidence

Insieme delle evidenze raccolte.

Le evidenze possono essere:

- osservate;
- inferite;
- ipotizzate.

Il sistema distingue sempre questi livelli.

---

# Professional Identity

Comprensione più stabile e coerente dell'identità professionale di una persona.

Non coincide con:

- CV;
- LinkedIn;
- lettera di presentazione.

Rappresenta il patrimonio informativo dal quale derivano tutte le rappresentazioni.

---

# Reference Model

Modello di riferimento costruito dal Core.

Descrive ciò che il sistema considera rilevante nel dominio analizzato.

Esempi:

- Role Model;
- Knowledge Model;
- Negotiation Model.

---

# Renderer

Componente che trasforma gli output del Core in una forma utilizzabile dall'utente.

Il Renderer non interpreta.

Visualizza.

---

# Representation

Forma concreta con cui una comprensione viene presentata.

Esempi:

- CV;
- report;
- LinkedIn;
- dashboard;
- checklist.

---

# Representation Strategy

Strategia che decide come rappresentare le informazioni.

Definisce:

- priorità;
- ordine;
- enfasi;
- livello di dettaglio;
- tono.

La Representation viene costruita solo dopo questa fase.

---

# Role Model

Specializzazione del Reference Model utilizzata nel dominio Interview.

Descrive ciò che deve emergere per risultare credibili in uno specifico contesto di selezione.

---

# Signal

Elemento osservabile appartenente ad una Dimension.

I Signals vengono resi visibili attraverso le Evidence.

---

# Visibility

Livello di osservabilità raggiunto rispetto al Reference Model.

Visibility non misura il valore.

Misura quanto il valore riesce a diventare osservabile.

---

# Visibility Analysis

Confronto tra:

Reference Model

e

Observed Evidence.

Produce:

- Coverage;
- Visibility Map;
- Gap;
- Priorità.

---

# Visibility Map

Rappresentazione di ciò che emerge e di ciò che rimane ancora poco osservabile.

Costituisce uno degli output principali del Core.

# Knowledge Extraction

Processo di trasformazione di informazioni destrutturate in conoscenza organizzata e riutilizzabile.

# Persistent Identity

Rappresentazione persistente costruita nel tempo attraverso l'accumulo e l'aggiornamento delle evidenze. Nel dominio Career coincide con l'evoluzione della Professional Identity.

(Non so ancora se questo termine entrerà davvero nel Core, ma lo terrei d'occhio.)

# Evidence Cache

Archivio persistente delle evidenze già estratte dalle sorgenti originali. Consente di evitare elaborazioni ripetute e riduce drasticamente il costo computazionale delle elaborazioni successive.
